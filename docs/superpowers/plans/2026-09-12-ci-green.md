## 根因（gh run 排查证据）

1. **2026-09-11 13:26 起所有工作流秒失败**：`gh run view 34604332640` 注解为
   `The job was not started because recent account payments have failed or your spending limit needs to be increased`，
   三个作业 0 步骤执行——账号级 billing 阻断，非仓库问题。私有仓库跑 macOS/Windows
   runner 消耗付费分钟；**用户将仓库转为 public（公开仓库标准 runner 免费）后解除**，
   `gh repo view --json visibility` 确认 `PUBLIC`。
2. **CI harness Linux 失败（run 34599030847，提交 19d46c8）**：biome "Found 1 error"
   于 `make lint`——该工作区后续已被 2026-09-12 full-check-repair 修复（本机 `make lint`
   与两轮 `make check` 均 0 错），随本次推送自然转绿。
3. **CI cli-portability Windows 失败**：`tests/doctor.rs` 两个测试在
   `serve_once`/redirect 线程 `stream.read().unwrap()` panic（日志行 doctor.rs:50:55）。
   根因：监听 socket `set_nonblocking(true)` 后，**Windows 的 accept 连接继承非阻塞模式**
   （Unix 不会），read 立即返回 WouldBlock。修复：accept 后 `set_nonblocking(false)`
   （两处，含注释）。本机 Linux 复验 `cargo test --test doctor` 6/6 通过；
   Windows 行为以推送后的 CI 为准（本机无 Windows 环境，此为唯一未本地验证项）。
4. **Build & Push windows 交叉编译失败**：`cross`（Linux 容器）编 x86_64-pc-windows-gnu
   时 `zerofrom v0.1.8` 报 E0463 `can't find crate zerofrom_derive`（proc-macro 未就位）。
   修复：CLI 矩阵改为 **release.yml 已验证结构**（v0.2.0 Release 成功实证）——musl 用
   cross、arm64 用 `ubuntu-24.04-arm` 原生 GNU、Windows 用原生 `x86_64-pc-windows-msvc`。
5. 顺带：`actions/checkout@v4` → `@v7.0.1`（Node 20 弃用告警），与 ci.yml 对齐；
   三个工作流 YAML 经 PyYAML 解析校验。
