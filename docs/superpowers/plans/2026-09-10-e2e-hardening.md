# E2E 与功能完整性加固

目标：基于当前产品实现继续优化，补足真实端到端测试，发现缺陷先RED再修复，最后重新执行完整harness。遵循原始产品范围；禁止浏览器自动化，不提交/推送，不使用真实HOME/凭证/业务数据库。

## 任务与验收

用户随后要求优先修复开发服务。先验证真实 `.env` 加载、数据库就绪、登录和开发代理；以隔离 `make up` 旅程防止健康检查成功但业务不可用。当前用户运行实例的数据库和进程不得由测试清理。

1. 真实Web→Go→PostgreSQL：Vitest/Testing Library挂载生产App，通过真实HTTP和Cookie调用启动的Go进程。注册/登录、创建令牌、管理员调账、工具/套餐/兑换、团队/设备、注销与权限恢复需消费真实JSON，不返回mock业务成功。独立test:e2e配置，普通单元测试不隐式跳过/伪称E2E完成。
2. 真实进程E2E：保留CLI旅程，提取可复用的隔离schema/临时服务fixture。覆盖Go重启后会话/撤销/账本保持、管理员配置HTTP上游→CLI桥接调用/定价、上游失败退款/不重放、共享数据库多服务额度/权限、过期pending重启恢复。断言实际HTTP、上游次数与数据库余额流水。
3. 网关审计与优化：针对取消、目录失效、会话生命周期、超时和大目录审查，实际复现再修复；正确性与有界资源一起验证，不靠纸面性能判断。
4. harness入口明确e2e范围，必须真实数据库与构建后二进制；现有check、CLI/Tauri/Web全部回归，独立审查新代码及验证覆盖。更新命令、证据与功能矩阵，保持人工GUI/外部供应商/非本机平台限制可见。

## 执行边界

按已授权当前工作区执行。使用subagent-driven-development分配Web E2E与网关任务，根代理负责进程E2E、harness和最终核对。新增集成测试首次即绿时标记覆盖已有行为；缺陷修复必须有真实RED。原有未提交修改全部保留。
